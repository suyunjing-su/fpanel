# Flux Panel 可视化功能与配置手册

> 适用版本：`3.0.28-beta`  
> 本文以当前面板实际界面、控制面校验和节点配置下发行为为准。所有带有“管理员”标识的页面或操作需要管理员角色。本文不会展示密码、节点密钥、验证码 Secret Key 或 Cloudflare Tunnel Token。

## 1. 使用范围、角色与界面模式

### 1.1 角色边界

| 角色 | 可以使用的主要功能 |
| --- | --- |
| 普通用户 | 登录、仪表板、本人有授权的转发、转发诊断、个人资料与改密。普通用户只能管理自己的转发，不能配置节点、隧道、用户、网站、运行策略、审计或运维恢复。 |
| 管理员 | 拥有全部普通用户功能，并可管理隧道、节点、限速、用户、网站配置、运行策略、运维与恢复、审计日志。 |
| 节点 | 不使用普通用户 JWT。节点以专用 Bearer secret 拉取完整运行配置；该密钥不在面板可视化页面中显示。 |

大多数配置变更会唤醒节点配置刷新队列；节点随后从控制面拉取完整配置并原子更新运行时配置。保存成功表示控制面已接受配置，不等于所有节点已经即时完成重载；应结合节点状态、故障事件和诊断结果确认。

### 1.2 桌面与 H5

- 窗口宽度不大于 768px、移动浏览器，或 URL 带 `?h5=true` 时使用 H5 布局。
- H5 底部主入口为：仪表板、转发、隧道（管理员）、节点（管理员）、我的。
- 桌面端侧栏提供完整管理员入口：仪表板、转发管理、隧道管理、节点监控、限速管理、用户管理、网站配置、运行策略、运维与恢复、审计日志。
- H5 的“我的”页可进入部分管理员页面；需要完整的批量管理、表格、策略编辑体验时建议使用桌面端。

### 1.3 页面清单

| 路径 | 页面 | 核心用途 |
| --- | --- | --- |
| `/` | 登录 | 用户认证与第三方验证码验证。 |
| `/change-password` | 强制改密 | 默认密码登录后必须修改账号与密码。 |
| `/dashboard` | 仪表板 | 套餐、权限、流量、转发和近 24 小时统计展示。 |
| `/forward` | 转发管理 | 创建和运行用户转发。 |
| `/tunnel` | 隧道管理 | 管理入口、链路、中继、出口与 TOT。 |
| `/node` | 节点监控 | 管理节点连接信息、端口、带宽与运行状态。 |
| `/limit` | 限速管理 | 管理隧道限速规则及用户-隧道的入口/出口策略。 |
| `/user` | 用户管理 | 管理用户套餐和隧道授权。 |
| `/config` | 网站配置 | 控制面地址、品牌和登录验证码配置。 |
| `/runtime-policy` | 运行策略 | 端点组、规则集、节点组和隧道绑定。 |
| `/operations` | 运维与恢复 | SQLite 备份、恢复、支持包与维护记录。 |
| `/audit` | 审计日志 | 读取控制面变更记录。 |
| `/profile` | 我的 | 当前账号信息、改密、退出和管理员快捷入口。 |
| `/settings` | 面板设置 | 浏览器本地保存的面板地址簿。 |

## 2. 登录、验证码、个人资料与密码

### 2.1 登录页面

| 选项 | 默认值与输入 | 效果与注意事项 |
| --- | --- | --- |
| 用户名 | 空，必填；提交时去除首尾空格。 | 用于控制面账号认证。 |
| 密码 | 空，必填，至少 6 位。 | 密码不会保存在页面配置或审计请求正文中。 |
| 登录 | 输入未在加载中时可单击，或按 Enter 提交。 | 验证通过后保存会话并进入仪表板。 |
| 第三方验证码 | 默认不出现；仅在网站配置启用验证码后出现。 | 提供商完成验证后，前端仅提交一次性证明，后端再向提供商复核。 |

验证码支持 GeeTest v4、Google reCAPTCHA Invisible、hCaptcha Invisible 和 Cloudflare Turnstile。它们均为第三方服务；没有内置/native CAPTCHA 选项。

首次使用默认账号密码成功登录时，系统会把会话导向 `/change-password`，必须完成改密才能继续使用。

### 2.2 强制修改密码

| 选项 | 规则 |
| --- | --- |
| 新用户名 | 必填，长度为 3–20。 |
| 当前密码 | 必填，用于确认账号所有权。 |
| 新密码 | 必填，长度为 6–20。 |
| 确认新密码 | 必填，且必须与新密码完全一致。 |
| 立即修改账号密码 | 成功后当前会话失效，必须使用新凭据重新登录。 |

### 2.3 “我的”页面

页面显示当前用户名、当前角色和客户端版本。管理员会看到限速管理、用户管理、网站配置、运维与恢复、审计日志等快捷入口。

**修改密码**弹窗包含“新用户名、当前密码、新密码、确认密码”。界面侧要求新用户名至少 3 位、新密码至少 6 位且两次密码相同；服务端仍会执行账号规则校验。成功后会清理当前会话并返回登录页。

**退出登录**会清理浏览器中的会话信息并回到登录页。

## 3. 仪表板

仪表板为只读监控和快捷查看页，不直接修改转发、隧道或套餐配置。

### 3.1 账户与流量展示

| 展示项 | 含义 |
| --- | --- |
| 流量配额、已用流量 | 由后端根据隧道的“流量计算”模式累计；页面直接展示入站与出站的已计费总量。 |
| 转发数量 | 当前用户实际拥有的转发数量及其套餐上限。 |
| 到期时间 | 无到期时间显示为“永久”；临近或过期会以提示颜色显示。 |
| 流量重置日 | `0` 为不自动重置；`1–31` 为每月相应日期零点重置。 |
| 近 24 小时流量图 | 按小时显示统计数据；没有采样数据的小时显示为 0。 |

`99999` 在用户与隧道配额展示中表示“无限制”。

### 3.2 到期通知

- 账户或授权隧道在 7 天内到期时，页面给出提醒。
- 次日到期与已过期会使用更醒目的提醒。
- 浏览器会记录已提醒的同一到期组合，避免重复弹出。

### 3.3 转发与地址复制

- 单个入口或远程地址可直接复制。
- 多个地址时打开地址列表，可逐条复制或一次复制全部。
- 普通用户可查看自己具有权限的隧道、已用流量、配额和对应转发；管理员主要看到控制面管理入口。

## 4. 转发管理

转发是用户实际对外开放的监听端口与远程目标之间的规则。创建前必须有可用、启用且未过期的隧道授权；入口节点必须在线。

### 4.1 列表、筛选与通用操作

| 选项/操作 | 说明 |
| --- | --- |
| 关键字 | 按转发名称等列表文本筛选。 |
| 状态 | 全部、运行、停止、异常。`正常/运行=1`，`暂停=0`，`异常=-1`。异常状态不能通过卡片开关直接恢复。 |
| 隧道 | 仅显示指定隧道的转发。 |
| 显示模式 | 平铺（direct）与分类（grouped）。选择会保存在当前浏览器的 `localStorage.forward-view-mode`。 |
| 拖拽排序 | 平铺模式可调整顺序；提交后保存排序。 |
| 启动/暂停 | 卡片开关把状态切换为运行或暂停。 |
| 编辑 | 修改可编辑字段；编辑时不能更换所绑定隧道。 |
| 诊断 | 对转发关联的节点链路及目标地址执行连通性检测；可重新诊断。 |
| 删除 | 需要确认。普通删除失败后可选择强制删除；强制删除用于无法确认节点侧清理时的管理操作，应先排查节点连通性。 |
| 批量删除 | 逐项返回成功或失败；可以重试失败项。 |
| 导入/导出 | 按隧道批量迁移转发定义，详见 4.4。 |

普通用户仅能读取、暂停、恢复、编辑、删除和诊断自己的转发；管理员可管理所有用户转发，并能填写高级运行控制。

### 4.2 新增/编辑转发表单

默认值：名称为空、未选择隧道、入口端口为空、远程地址为空、负载策略为 `fifo`、连接数限制为 `0`、来源规则为黑名单、Proxy Protocol 收发关闭。

| 字段 | 值、默认与校验 | 运行效果 |
| --- | --- | --- |
| 转发名称 | 必填；控制面最长 100 字符。 | 用于识别规则。 |
| 选择隧道 | 必选；编辑时不可更换。 | 决定入口节点、可分配端口与用户授权范围。 |
| 入口端口 | 可留空；填写范围为 1–65535，且必须属于所有入口节点的公共可用端口范围。 | 留空时控制面从入口节点端口范围自动选择未被占用的端口，并进行数据库预约和节点端口可用性检查。 |
| 远程地址 | 多行，每行一个 `host:port`；IPv6 使用 `[IPv6]:port`。 | 至少需要远程地址或端点组之一。保存时规范化为逗号分隔列表。 |
| 负载策略 | 单一远程地址时固定为 `fifo`；多地址或端点组时可选择。 | `fifo` 按主备顺序；`round` 轮询；`rand` 随机；`hash` 为按源 IP 哈希。控制面会将未支持的策略归一为 `fifo`。 |
| 出口网卡名或 IP | 可选。 | 多网卡/多地址节点上指定访问远程目标时的出口接口或源地址。 |

#### 管理员高级设置

以下折叠区域只有管理员可配置；普通用户的请求会被控制面拒绝或清除这些高级字段。

| 字段 | 可选值/规则 | 效果 |
| --- | --- | --- |
| 端点组 | 可选，选择已启用且至少有一个启用端点的端点组。 | 可让远程地址留空，使用端点组的健康探测、主备或加权路由。 |
| 路由规则集 | 选择端点组后才可选择；规则所引用的端点必须属于所选端点组，规则集必须启用。 | 根据客户端 IP、协议或可观测的 HTTP 属性选择端点。 |
| 总连接数上限 | 非负整数，默认 `0`。 | `0` 表示不限制该转发的总并发连接数。 |
| 单 IP 连接数上限 | 非负整数，默认 `0`。 | `0` 表示不限制单个来源 IP 的并发连接数。 |
| 来源规则模式 | `黑名单（命中时拒绝）=0`；`白名单（仅命中时允许）=1`。 | 与“来源 IP/CIDR”共同决定入站准入。 |
| 来源 IP/CIDR | 多行，每行一个 IP 或 CIDR。 | 黑名单模式拒绝命中来源；白名单模式仅允许命中来源。无条目时不要把白名单模式当作“允许所有”。 |
| 接收 Proxy Protocol | `关闭=0`、`v1=1`、`v2=2`。 | 让入口监听端解析上游发送的 Proxy Protocol。只有上游确实发送相同版本时才启用。 |
| 发送 Proxy Protocol | `关闭=0`、`v1=1`、`v2=2`。 | 向远程目标发送 Proxy Protocol。目标不支持时必须关闭。 |

### 4.3 诊断结果

诊断不是持续健康检查，而是按请求触发的检查。结果含检查描述、发起节点、目标地址和端口、平均耗时、丢包率与错误信息。它用于判断入口到下一跳、链路中继到下一跳、出口到远程地址的可达性。

### 4.4 导入与导出

**导出**：选择一个隧道后生成文本，每行格式为：

```text
目标地址|转发名称|入口端口
```

远程地址可以包含逗号分隔的多个目标。可复制生成文本；如果所选隧道没有转发，不能生成有效导出内容。

**导入**：先选择目标隧道，再粘贴上述格式的多行文本。

- 目标地址和转发名称为必填；入口端口可空。
- 端口填写时必须为 1–65535；空端口交由系统自动分配。
- 每行独立创建，页面会显示逐行成功/失败结果。
- 导入创建的负载策略统一为 `fifo`；需要轮询、随机、端点组或高级策略时，应导入后逐条编辑。

## 5. 隧道管理

隧道定义入口节点、可选中继链、出口节点及其节点间传输方式。删除隧道不可恢复，且会影响关联的转发和用户授权，应先迁移或删除依赖资源。

### 5.1 列表与操作

| 操作 | 说明 |
| --- | --- |
| 关键字/类型筛选 | 可按名称及隧道类型筛选；类型包括端口转发和隧道转发。 |
| 新增/编辑 | 打开完整拓扑配置。编辑时隧道类型不能修改。 |
| 诊断 | 依次检查入口、中继、出口到目标链路的连通性。 |
| TOT 密钥轮换 | 仅对启用 TOT 的隧道有效。生成新的密钥并触发节点刷新；密钥不会通过管理 API 返回，也不会在列表中显示。 |
| 故障事件 | 可按健康/带宽超载事件类型，以及“仅活跃/全部历史”筛选。用于查看出口、配额或带宽故障的产生与解决状态。 |
| 删除/批量删除 | 需要确认；批量操作可显示失败项并重试。 |

### 5.2 基础隧道字段

默认值：类型为端口转发、流量计算为单向、流量倍率为 `1.0`、入口/出口/中继为空、TOT 默认关闭。

| 字段 | 值与校验 | 效果 |
| --- | --- | --- |
| 隧道名称 | 必填；控制面最长 100 字符。 | 管理页面和授权列表中的名称。 |
| 隧道类型 | `端口转发=1`、`隧道转发=2`；编辑时锁定。 | 端口转发不配置中继/出口链；隧道转发可配置中继与出口。 |
| 流量计算 | `单向计算（仅上传）=1`、`双向计算（上传+下载）=2`。 | 决定用户和用户隧道的流量累计方式。 |
| 流量倍率 | 数值，范围 `0–100`，默认 `1.0`。 | 对计费流量应用倍率；应避免设为 0 或异常倍率造成不可预期的套餐统计。 |
| 入口 IP | 多行 IP 或域名；可留空。 | 每行一个。留空时，控制面使用入口节点的 `serverIp` 生成入口地址。 |
| 入口节点 | 多选，至少选择一个在线节点。 | 定义对外入口；一个节点不能同时被选作同一隧道的入口、中继或出口。 |
| 出口节点 | 仅“隧道转发”显示，多选；链式隧道至少需要一个在线出口。 | 定义最终出站节点。 |
| 状态 | 创建与更新请求会携带状态；非零归一为启用。 | 当前主表单没有单独状态开关，应通过隧道资源与关联转发的运行操作管理实际业务。 |

### 5.3 中继链与出口链

仅“隧道转发”可添加中继跳数；每跳可以选多个在线节点。

| 字段 | 选项 | 效果 |
| --- | --- | --- |
| 添加一跳/删除一跳 | 可建立或移除一层中继组。 | 跳数决定入口到出口的拓扑顺序。 |
| 节点 | 每跳多选；已作为入口、出口或其他跳的节点不可重复选择。 | 同一跳中的多个节点根据该跳策略选择。 |
| 协议 | `TCP`、`UDP+QUIC`、`UDP+KCP`、`MPTCP`。 | 节点间传输协议。当前产品不提供 HTTP/3、0-RTT、Noise 或数据面 mTLS 的表单选项。 |
| 负载策略 | `主备(fifo)`、`轮询(round)`、`随机(rand)`。 | 选择同一跳或出口组中的节点。 |

出口区域同样提供“节点、协议、负载策略”，作用于出口节点组。协议为空时控制面默认 TCP；历史 `mtcp` 值会规范化为 `mptcp`。

### 5.4 TOT 多线路传输

TOT 是多路径传输、带宽聚合和路径故障恢复功能，**不是 TLS、Noise 或其他载荷机密性协议**。应继续使用适合业务的端到端加密来保护敏感数据。

TOT 只可在“隧道转发”类型中启用。当前界面可配置的默认值为：线路数 `2`、分片 `32768` 字节、发送窗口 `256`、重传间隔 `300ms`、最大重试 `20`、恢复间隔 `1000ms`、握手超时 `5000ms`、空闲回收 `300000ms`、MPTCP 关闭。控制面还保存最大时钟偏差默认 `30000ms`，但当前界面未提供其输入项。

| 字段 | 默认值与限制 | 效果与建议 |
| --- | --- | --- |
| 启用 TOT | 默认关闭。 | 开启多线路传输配置。 |
| 线路数 | 默认 `2`。 | 并行路径数量；应与实际链路和资源容量相匹配。 |
| 分片字节 | 默认 `32768`。 | 每个 TOT 帧的最大载荷。增大可降低协议开销但可能加大单次丢失代价。 |
| 发送窗口 | 默认 `256`。 | 未确认帧的并发窗口；过大可能增加内存和重传压力。 |
| 最大重试 | 默认 `20`。 | 单帧重传上限。 |
| 独立线路地址 | 可为空；每行一个 `host:port`，最多 16 条。 | 填写后，线路数会以去重后的地址数为准。只适用于无中继、恰好一个出口的拓扑；为空时仅建立到拓扑目标的并行连接，不能提供独立故障域。 |
| 重传间隔(ms) | 默认 `300`。 | 未确认帧的重传周期。 |
| 恢复间隔(ms) | 默认 `1000`。 | 失效路径的重试/恢复周期。 |
| 握手超时(ms) | 默认 `5000`。 | 建立 TOT 会话允许的最大握手时间。 |
| 空闲回收(ms) | 默认 `300000`。 | 无活动会话的回收时间。 |
| 启用端到端内核 MPTCP | 默认关闭。 | 要求发起端和监听端内核都支持 MPTCP；通过其他代理链拨号会拒绝启动，避免静默降级为普通 TCP。显式路径或 MPTCP 都要求无中继、单出口。 |
| 密钥状态 | 编辑已启用 TOT 的隧道时只读显示“已配置/未配置”。 | 密钥无法查看；需要更换时使用卡片上的“轮换密钥”。 |

### 5.5 隧道约束

- 所有参与节点必须存在、在线、ID 唯一；离线节点不能被提交到新拓扑。
- 链式隧道必须至少有一个出口节点。
- 明确路径或 TOT MPTCP 时，不能有中继跳数且只能选择一个出口节点。
- 端口、配额、带宽等链路级策略应优先使用“运行策略”的隧道节点组绑定，便于批量维护。

## 10. 运行策略

运行策略为管理员高级功能。保存端点组、规则集、节点组或绑定后，会触发节点配置刷新。被转发或隧道引用的资源不能直接删除。

### 10.1 端点组

端点组用于将多个远程目标作为一个健康检查与选择单元提供给转发使用。

默认值：策略 FIFO、失败阈值 `1`、失败冷却 `600000ms`、探测间隔 `10000ms`、探测超时 `3000ms`、启用；初始含一个空端点。

| 字段 | 值与限制 | 效果 |
| --- | --- | --- |
| 名称 | 必填，最长 100 字符。 | 标识端点组。 |
| 描述 | 可选。 | 管理说明，不参与转发匹配。 |
| 选择策略 | FIFO（主备顺序）、轮询、随机（按权重）。 | 决定健康端点的选择方式。 |
| 最大失败次数 | 默认 1，正数。 | 连续失败达到阈值后将端点视为失败。 |
| 失败冷却(ms) | 默认 600000。 | 失败端点的暂时隔离时长。 |
| 探测间隔(ms) | 默认 10000。 | 周期性探测频率。 |
| 探测超时(ms) | 默认 3000。 | 单次探测等待时间。 |
| 启用状态 | 启用/禁用。 | 只有启用的组可被新的转发选择。 |
| 添加端点/删除端点 | 至少保留一个有效端点。 | 管理端点列表。 |
| 端点名称 | 必填且组内唯一。 | 管理展示。 |
| 地址 | 必填 `host:port`，组内唯一。 | 实际远程目标。 |
| 优先级 | 非负整数，默认 0。 | FIFO 主备选择时的优先级依据。 |
| 权重 | `1–100`，默认 1。 | 随机策略的相对选择权重。 |
| 排序 | 非负整数，默认 0。 | 相同优先级时的稳定排序。 |
| 备用 | 开关，默认关闭。 | 标记为备用端点，供主备故障切换。 |
| 端点启用 | 开关，默认启用。 | 禁用端点不参与选择。 |

### 10.2 路由规则集

规则集将请求属性匹配到一个或多个端点。只有绑定到转发，并且其端点全部属于该转发所选端点组时才生效。UDP 只能使用节点能观测到的规则，不应假设所有 HTTP 七层属性在 UDP 流量中可用。

默认值：名称和描述为空、规则集启用、初始含一条规则；规则默认匹配类型为客户端 IP、优先级 100、启用、非反向匹配、无端点。

| 字段 | 规则 |
| --- | --- |
| 规则集名称 | 必填，最长 100 字符。 |
| 描述 | 可选。 |
| 启用状态 | 启用/禁用整个规则集。 |
| 添加规则/删除规则 | 管理规则顺序与数量。规则名称在同一规则集中必须唯一。 |
| 规则名称 | 必填。 |
| 匹配类型 | 见下表。 |
| 匹配值 | 必填；按匹配类型接受 IP/CIDR、协议、Host、方法、路径、请求头、查询参数或正则。 |
| 次要参数 | 对需要名称和值的类型提供补充参数，例如 Header/Query 名称或匹配辅助值；应按页面提示与匹配类型填写。 |
| 优先级 | 正整数，默认 100。数值决定规则评估优先级。 |
| 排序 | 非负整数，默认 0。优先级相同时的稳定顺序。 |
| 反向匹配 | 默认关闭。开启后表示“不匹配此条件”才命中。 |
| 启用状态 | 单条规则是否参与评估。 |
| 目标端点 | 多选；必须选择存在的端点，并且在转发使用时属于选定端点组。 |

匹配类型：

| 类型 | 含义 |
| --- | --- |
| 客户端 IP (`client_ip`) | 匹配来源 IP 或 CIDR。 |
| 协议 (`protocol`) | 匹配可识别协议。 |
| Host (`host`) | 精确 Host 匹配。 |
| Host 正则 (`host_regexp`) | Host 的正则表达式匹配。 |
| 方法 (`method`) | HTTP 方法匹配。 |
| 路径 (`path`) | 精确路径匹配。 |
| 路径正则 (`path_regexp`) | 路径正则表达式匹配。 |
| 路径前缀 (`path_prefix`) | 路径以前缀开头时匹配。 |
| 请求头 (`header`) | HTTP Header 条件匹配。 |
| 请求头正则 (`header_regexp`) | Header 值正则匹配。 |
| 查询参数 (`query`) | URL Query 条件匹配。 |
| 查询参数正则 (`query_regexp`) | Query 值正则匹配。 |

正则表达式必须通过控制面校验。请避免编写高复杂度、可能造成高匹配开销的正则。

### 10.3 节点组

节点组将一批节点以统一的健康与主备策略绑定进隧道拓扑。

默认值：策略 FIFO、最大失败次数 `1`、失败冷却 `600000ms`、启用；初始含一个空成员。

| 字段 | 值与限制 | 效果 |
| --- | --- | --- |
| 名称 | 必填，最长 100 字符。 | 标识节点组。 |
| 描述 | 可选。 | 管理说明。 |
| 选择策略 | FIFO（主备）、轮询、随机（按权重）。 | 节点组成员的选择方式。 |
| 最大失败次数 | 必须大于 0。 | 到阈值后进入故障处理。 |
| 失败冷却(ms) | 至少 1000ms，默认 600000ms。 | 故障成员的冷却时长。 |
| 启用状态 | 启用/禁用。 | 绑定时必须为启用状态。 |
| 节点 | 必选，组内不能重复。 | 绑定已有节点。 |
| 优先级 | 非负整数。 | 主备/选择排序依据。 |
| 排序 | 非负整数。 | 相同优先级的稳定顺序。 |
| 备用 | 开关。 | 标记成员为备用节点。 |

### 10.4 隧道节点组绑定

该功能将节点组展开为指定隧道中的入口、中继或出口节点，并可为链路定义端口、协议、流量配额和限速。

默认值：未选择隧道/节点组、链路类型为入口、端口 0、策略 FIFO、跳序号 0、协议 TCP、流量配额 0、速度限制 0。

| 字段 | 值与限制 | 效果 |
| --- | --- | --- |
| 隧道 | 必选。 | 要更新的目标隧道。 |
| 节点组 | 必选，必须启用且至少有一个成员。 | 被展开到目标拓扑。 |
| 链路类型 | `入口=1`；链式隧道可选 `中继=2`、`出口=3`。直连隧道只能绑定入口。 | 决定节点组位于隧道的哪个位置。 |
| 监听端口 | `1–65535`。 | 为该链路分配端口；更新时会同步既有转发端口。 |
| 选择策略 | FIFO、轮询、随机。 | 应用于展开后的节点组。 |
| 跳序号 | 中继类型必须大于 0；入口和出口必须为 0。 | 标识第几跳中继。 |
| 协议 | TCP、UDP+QUIC、UDP+KCP、MPTCP。 | 节点之间的传输方式。 |
| 流量配额(字节) | 非负，`0` 表示未设置该链路级配额。 | 针对这段拓扑的资源限制。 |
| 速度限制(Mbps) | 非负，`0` 表示未设置该链路级限速。 | 针对这段拓扑的带宽限制。 |

新增入口节点前，控制面会检查端口预约与可用性；修改节点组或绑定时，控制面会重建相应 `tunnel_nodes` 并同步相关转发端口。生产环境应先评估端口冲突和用户业务影响。

## 14. Cloudflare Tunnel 部署说明（部署配置，不是面板页面选项）

当主机的 80/443 已被其他服务占用、且不希望改动现有服务时，可以在安装器中选择 **Cloudflare Tunnel** 模式。

### 14.1 与直连 Caddy 的区别

| 模式 | 主机端口 | 入口 TLS | 使用前提 |
| --- | --- | --- | --- |
| 直连 Caddy | 需要独占所选 IPv4 的 TCP 80、TCP 443、UDP 443。 | Caddy 直接获取并终止证书。 | 域名 DNS 指向主机，且端口未被其他服务占用。 |
| Cloudflare Tunnel | 不发布主机 80/443/UDP 443。 | 浏览器到 Cloudflare Edge 使用 HTTPS；Tunnel 到 Docker 内部 Caddy 使用 HTTP。 | 已在 Cloudflare Zero Trust 创建 Tunnel、配置 Public Hostname，并获得该 Tunnel 的 token。 |

Cloudflare 模式的 `cloudflared` 仅通过 Docker bridge 网络连接内部 `ingress` 服务，因此不会争抢现有主机端口。内部 Caddy 关闭自动 HTTPS；不要把这条 Docker 内部 HTTP 连接错误理解为浏览器侧降级为 HTTP。

### 14.2 安装器选项

| 安装项 | 说明 |
| --- | --- |
| 面板域名 | 必须是有效域名；直连模式需解析到本机，Cloudflare Tunnel 模式需在 Cloudflare Public Hostname 中配置。 |
| 直连 Caddy | 可输入 `PANEL_BIND_ADDRESS`。默认 `0.0.0.0`；如果主机有独立 IPv4，可填该 IP 以避开其他 IP 上的端口占用。安装器会先用临时容器真实测试 80/443 TCP 和 443 UDP 绑定；失败时不会停止、修改或覆盖已有服务。 |
| Cloudflare Tunnel token | 选择 Cloudflare Tunnel 后以不回显方式输入。token 仅写入部署目录 `.env`，权限为 `0600`，并经环境变量 `TUNNEL_TOKEN` 注入 cloudflared；不会放进命令行参数或文档示例。 |

在 Cloudflare Zero Trust 中创建 Public Hostname 时，将 `https://你的面板域名` 指向 `http://ingress:80`。这项配置在 Cloudflare 控制台完成，安装器不会代替用户创建 Tunnel、DNS 或 Public Hostname。

### 14.3 安全和运维建议

- Cloudflare Tunnel 仅解决入口端口占用与连接方式，不替代控制面到节点的 HTTPS 要求。
- 网站配置中的“面板后端地址/连接协议”仍应配置为节点能访问的 HTTPS 地址；节点控制面不会接受 HTTP。
- 不要把 Tunnel token、验证码 Secret Key、JWT secret、metrics token 或节点 secret 粘贴到工单、审计备注或导出文本。
- 更新 Cloudflare 模式部署时，安装器会根据 `.env` 中存在的 Tunnel token 保持 Cloudflare Compose 模式，避免意外切换为直连端口发布模式。

## 15. 配置后的检查顺序

1. **网站配置**：先填写可从节点访问的 HTTPS 控制面地址，再生成节点安装命令。
2. **节点**：确认节点在线、端口范围正确、监听地址和带宽约束符合网络实际情况。
3. **隧道**：创建入口和需要的中继/出口拓扑；若使用 TOT，先确认拓扑满足单出口/无中继等限制。
4. **用户与授权**：创建用户、设置到期与配额，再授予目标隧道权限。
5. **转发**：创建远程目标、入口端口和必要的管理员高级策略。
6. **运行策略**：需要健康探测、端点路由或节点组故障转移时，再建立端点组、规则集、节点组和绑定。
7. **验证**：检查节点监控、隧道/转发诊断、故障事件和审计日志；升级或批量变更前下载数据库备份。
